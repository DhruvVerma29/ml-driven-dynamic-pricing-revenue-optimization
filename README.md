# Dynamic Pricing & Inventory-Constrained Optimiser

A machine-learning pricing tool that predicts how many units a product will sell at different prices, respects the stock on hand, and recommends the price that maximises daily revenue (or profit, when a unit cost is supplied). It comes with an interactive Streamlit dashboard for exploring pricing decisions product by product and region by region.

---

## What it does

For one product, in one region, on one day, the app:

1. Takes the current situation (channel, month, day of week, stock level, recent sales, unit cost).
2. Simulates a grid of candidate prices between a chosen minimum and maximum percentage of the base price.
3. Predicts demand at each price with a gradient-boosted model.
4. Caps sales at available inventory: `units sold = min(predicted demand, stock)`.
5. Computes revenue or profit at each price and returns the optimum.

The dashboard shows the best price, expected units sold, expected revenue or profit per day, the improvement over the current price, and the price elasticity of the product's category.

## Dataset

`retail_pricing_demand_100k.csv` contains daily sales records for products sold across regions and channels.

| Column | Description |
|---|---|
| `date` | Day of the record |
| `product_id`, `category`, `brand` | Product identity and attributes |
| `region`, `channel` | Where and how the product was sold (e.g. web, mobile, app) |
| `season` | Season of the year |
| `base_price`, `current_price` | List price and the price charged that day |
| `price_change_pct`, `discount_pct` | Size of the price change / discount |
| `promotion_type` | Promotion label (e.g. Buy One Get One, None) |
| `units_sold`, `revenue` | Sales outcome |
| `inventory_level`, `stockout_flag` | Stock on hand and stockout indicator |
| `demand_index` | Demand signal |

Each **series** is one product in one region, observed once per day.

## Modelling approach

### Features
- **Price features:** base price, current price, price ratio (current / base), discount percentage, discount depth
- **Calendar features:** day of week, month, weekend flag
- **Recent demand:** 7-day and 14-day rolling average of units sold per series (lagged by one day so a day's own sales are never used to predict it)
- **Context:** inventory level, category, brand, region, channel, season, promotion type

### Models compared
| Model | Description |
|---|---|
| Naive | Tomorrow's sales equal yesterday's sales |
| Log-log regression | `ln(units) = a + b · ln(price_ratio)` using price only, with smearing correction for back-transformation |
| Gradient boosting (XGBoost) | Leaf-wise trees with categorical support; the number of trees is tuned on a validation slice taken from the end of the training period |

### Evaluation
- **Time-based split:** the earliest 80% of dates are used for training and the latest 20% for testing
- **Metrics:** MAE, RMSE, WAPE and R²
- **Price-response check:** confirms the model's predicted demand falls as price rises
- **Revenue lift:** compares revenue from the optimised price against both actual revenue and the model's revenue at historical prices

### Price elasticity
Elasticity is estimated with a within-series (fixed-effects) log-log regression, in which each product-region is compared with itself. This is reported overall (with standard error) and by category.

### Price optimisation
For every candidate price ratio, the optimiser rewrites the price-related features (price, ratio, discount, discount depth) and the matching promotion label, holds everything else fixed, predicts demand, applies the inventory cap and selects the revenue-maximising (or profit-maximising) price.

## Getting started

### 1. Install dependencies

```bash
pip install numpy pandas scikit-learn xgboost streamlit plotly
```

### 2. Train the model

```bash
python Train.py
```

This prints the data summary, the model comparison table, elasticity estimates and revenue lift, and saves everything the app needs to `pricing_model.pkl`.

### 3. Launch the dashboard

```bash
streamlit run app.py
```

## Using the dashboard

**Sidebar – Situation**
- Product and region
- Channel, month and day of week
- Units in stock
- Average daily units over the last 7 and 14 days
- Unit cost (leave at 0 to maximise revenue; enter a cost to maximise profit)

**Sidebar – Prices**
- Price search range, as a percentage of base price
- Current price, as a percentage of base price

**Main panel**
- Headline metrics: best price, units sold, revenue or profit per day (each compared with the current price), and category price elasticity
- **Demand vs price** chart with the stock level and current price marked
- **Revenue / Profit vs price** chart with the current and best prices marked
- Expandable table with the numbers behind the charts
- Expandable model-validation section with the training and test periods, model comparison table, price-response check, elasticity estimate and revenue-lift results

## Key concepts

- **Demand forecasting** with gradient boosting on price, calendar, inventory and recent-sales features
- **Price elasticity** estimation using within-series log-log regression
- **Constrained optimisation** of revenue or profit under an inventory limit
- **Time-aware validation** with a chronological train/test split and leakage-free lag features
